# useCalendarApp 레퍼런스

`useCalendarApp(config: CalendarAppConfig)`은 DayFlow 코어를 애플리케이션과 연결해 주는 훅입니다. 설정 객체 하나를 전달해 뷰를 등록하고, 초기 이벤트를 넣고, 선택적 UI를 켜고, 생명주기 콜백을 연결합니다. 이 문서에서는 사용할 수 있는 모든 옵션을 살펴봅니다.

## 설정 한눈에 보기

| 옵션                   | 타입                        | 필수 여부 | 기본값                                       | 설명                                                                                                                                          |
| ---------------------- | --------------------------- | --------- | -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `views`                | `CalendarView[]`            | 필수      | —                                            | 뷰 정의를 등록합니다(예: `createMonthView()`). 최소 하나는 있어야 합니다.                                                                     |
| `plugins`              | `CalendarPlugin[]`          | 선택      | `[]`                                         | 선택적 플러그인(드래그 도우미, 단축키 등)을 설치합니다. 각 플러그인은 `install` 시점에 앱 인스턴스를 전달받습니다.                            |
| `events`               | `Event[]`                   | 선택      | `[]`                                         | 초기 이벤트 목록입니다. 이후에는 `addEvent`/`updateEvent`로 상태를 변경하세요.                                                                |
| `callbacks`            | `CalendarCallbacks`         | 선택      | `{}`                                         | 뷰·날짜·이벤트가 바뀔 때 실행되는 생명주기 훅입니다. API와 동기화하기에 적합합니다.                                                           |
| `defaultView`          | `ViewType`                  | 선택      | `ViewType.WEEK`                              | 처음 로드되는 뷰입니다. `views`에 포함되어 있어야 합니다.                                                                                     |
| `initialDate`          | `Date`                      | 선택      | `new Date()`                                 | 처음 포커스할 날짜입니다(표시할 월 계산의 기준이기도 합니다).                                                                                 |
| `timeZone`             | `string`                    | 선택      | 사용자의 시스템 시간대                       | 모든 뷰에서 사용하는 전역 표시·편집 시간대입니다.                                                                                             |
| `timeFormat`           | `'12h' \| '24h'`            | 선택      | —                                            | 모든 뷰·검색·컴포넌트에 적용되는 전역 시간 형식입니다. 우선순위가 가장 높아 뷰 단위나 검색 단위 설정을 덮어씁니다.                            |
| `switcherMode`         | `'buttons' \| 'select'`     | 선택      | `'buttons'`                                  | 헤더에 내장된 뷰 전환기의 표시 방식을 제어합니다.                                                                                             |
| `calendars`            | `CalendarType[]`            | 선택      | `[]`                                         | 캘린더 분류(업무, 개인 등)를 색상·표시 여부와 함께 등록합니다.                                                                                |
| `defaultCalendar`      | `string`                    | 선택      | 처음 표시되는 캘린더                         | 새 이벤트를 만들 때 사용할 ID입니다.                                                                                                          |
| `theme`                | `ThemeConfig`               | 선택      | `{ mode: 'light' }`                          | 전역 테마 모드와 필요 시 토큰 재정의를 설정합니다.                                                                                            |
| `locale`               | `string \| Locale`          | 선택      | `'en-US'`                                    | 국제화(i18n)에 사용할 로케일을 설정합니다. 언어 코드(예: 'ja')나 Locale 객체를 지원합니다.                                                    |
| `calendarSystem`       | `'gregorian' \| 'jalali'`   | 선택      | `'gregorian'`                                | 날짜 표시와 이동에 사용할 달력입니다. `'jalali'`는 페르시아 태양력입니다. [calendarSystem](#calendarsystem)을 참고하세요.                     |
| `useEventDetailDialog` | `boolean`                   | 선택      | `false`                                      | 인라인 패널 대신 기본 모달 상세 대화상자를 사용합니다.                                                                                        |
| `eventDetailTrigger`   | `'click' \| 'dbClick'`      | 선택      | `'dbClick'`                                  | 데스크톱에서 이벤트 상세를 한 번 클릭으로 열지 더블 클릭으로 열지 결정합니다. 터치 입력에서는 항상 한 번 탭하면 열립니다.                     |
| `useCalendarHeader`    | `boolean`                   | 선택      | `true`                                       | 기본 헤더를 표시하거나(`true`) 숨깁니다(`false`). 직접 만든 헤더를 쓰려면 `DayFlowCalendar`의 `calendarHeader` 슬롯을 사용하세요.             |
| `readOnly`             | `boolean \| ReadOnlyConfig` | 선택      | `false`                                      | 내장 편집 UI를 비활성화합니다. 불리언이나 세부 제어용 설정(드래그/조회)을 지정할 수 있습니다. 코드에서 호출하는 이벤트 API는 계속 동작합니다. |
| `enableTasks`          | `boolean`                   | 선택      | `false`                                      | 내장 편집기에 일정 / 할 일 전환을 표시합니다. 꺼져 있어도 기존 할 일은 편집할 수 있습니다. [할 일](/docs-ko/features/tasks).                  |
| `allDaySortComparator` | `AllDaySortComparator`      | 선택      | 캘린더 그룹 순서, 여러 날 종일 이벤트가 먼저 | 모든 뷰에서 종일 이벤트 행의 정렬 순서를 제어하는 사용자 정의 비교 함수입니다. 지정하면 기본 정렬을 완전히 대체합니다.                        |

## 주요 옵션

### Views (필수)

- 각 뷰는 `{ type, component, config }` 형태의 `CalendarView` 객체입니다.
- DayFlow는 바로 사용할 수 있는 정의를 반환하는 팩토리(`createDayView`, `createWeekView`, `createMonthView`, `createAgendaView`, `createYearView`)를 제공합니다.
- `defaultView`는 등록된 뷰 타입 중 하나와 일치해야 합니다. 그렇지 않으면 초기화 과정에서 오류가 발생합니다.

### Events

- 전달한 배열이 메모리상의 `CalendarApp.state.events` 목록이 됩니다.
- `useCalendarApp`은 앱의 변경을 감시하므로 `calendar.addEvent()`나 `calendar.updateEvent()`를 호출하면 애플리케이션 상태가 자동으로 동기화됩니다.
- 이벤트가 `Event` 인터페이스를 따르는지 확인하세요(`start`/`end`는 `PlainDate`, `PlainDateTime`, `ZonedDateTime`을 받습니다).

### Plugins

- 플러그인은 `{ name, install(app), config }` 형태이며 생성 시 한 번만 실행됩니다.
- 플러그인으로 드래그 핸들러, 키보드 단축키, 분석 옵저버를 등록하거나 `app.getPlugin(name)`으로 자체 API를 노출할 수 있습니다.

### Callbacks

`callbacks`는 상태를 백엔드나 분석 계층과 동기화된 상태로 유지해 줍니다:

- `onViewChange(view)`는 뷰 전환이 성공한 뒤에 호출됩니다.
- `onDateChange(date)`는 포커스된 날짜가 바뀔 때마다 호출됩니다(이동 또는 선택).
- `onVisibleRangeChange(start, end, reason)`은 표시 중인 날짜 범위가 바뀔 때 호출됩니다. 별도 계산 없이 더 정확한 범위로 데이터를 가져올 수 있습니다.
- `onEventCreate(event)`, `onEventUpdate(event)`, `onEventDelete(id)`는 CRUD 작업에 대응합니다. API 동기화에 적합합니다.
- `onEventDoubleClick(event, e)`는 기본 모드인 `eventDetailTrigger: 'dbClick'`에서 이벤트를 더블 클릭할 때 호출됩니다. 외부 팝오버의 기준점으로 `e.currentTarget`을 사용하고, DayFlow 기본 상세 패널·대화상자를 막으려면 `false`를 반환하세요.
- `onMoreEventsClick(date)`는 월 뷰에서 "+ X개 더" 링크를 클릭할 때 호출됩니다.
- `onCalendarCreate(calendar)`, `onCalendarUpdate(calendar)`, `onCalendarDelete(id)`는 캘린더 CRUD 작업에 대응합니다.
- `onCalendarMerge(sourceId, targetId)`는 두 캘린더를 병합할 때 호출됩니다(예: "업무"를 "개인"에 합치는 경우).
- `onRender()`는 캘린더가 렌더링을 한 차례 마쳤을 때 실행됩니다(계측에 유용합니다).

### defaultView와 initialDate

- `defaultView`는 초기 `state.currentView`를 정합니다. 지정하지 않으면 DayFlow가 `ViewType.WEEK`로 되돌아가므로, 뷰가 하나뿐인 캘린더에서는 명시적으로 지정하세요.
- `initialDate`는 `state.currentDate`와 내부 `visibleMonth`를 함께 초기화합니다. 라우팅이나 사용자 설정에서 날짜를 가져온다면 이 값을 바꾸세요.

### timeZone

- `timeZone`은 일·주·월·아젠다·연간 뷰의 기본 표시 및 편집 시간대를 정합니다.
- 지정하지 않으면 DayFlow가 사용자의 시스템 시간대에서 값을 가져옵니다.
- `timeZone`을 바꾸면 UI가 다시 계산되어 표시되지만, 그 자체로 이벤트 데이터가 바뀌지는 않습니다.
- 변경이 적용된 뒤에도 편집 콜백은 정규화된 이벤트 데이터를 반환합니다. DayFlow는 임시 표시용 시간대를 저장 형태로 남기지 않습니다.
- 일·주 뷰의 `secondaryTimeZone`은 표시 전용 참조 축일 뿐이며, 앱의 기본 시간대를 대체하지 않습니다.

### switcherMode

- `'buttons'`: 가로 버튼 그룹으로 표시합니다. 데스크톱에 적합합니다.
- `'select'`: 드롭다운으로 표시합니다. 공간이 부족하거나 뷰 타입이 많을 때 유용합니다.

### calendars와 defaultCalendar

- `calendars`는 각 캘린더 타입(`id`, `name`, `colors`, 표시 여부)을 정의합니다. 캘린더 레지스트리가 `theme.mode`(`'light' | 'dark' | 'auto'`)에 따라 밝은 색상과 어두운 색상을 자동으로 선택합니다.
- `defaultCalendar`는 새 이벤트가 어떤 캘린더를 상속할지 정합니다. 지정하지 않으면 처음 표시되는 캘린더가 사용됩니다.

**`CalendarType`의 속성:**

| 속성           | 타입                     | 필수 여부 | 설명                                                                 |
| -------------- | ------------------------ | --------- | -------------------------------------------------------------------- |
| `id`           | `string`                 | 예        | 고유 식별자입니다(예: `'work'`, `'personal'`).                       |
| `name`         | `string`                 | 예        | UI에 표시되는 이름입니다.                                            |
| `colors`       | `CalendarColors`         | 예        | 라이트 모드 색상 세트입니다(아래 참고).                              |
| `darkColors`   | `CalendarColors`         | 아니오    | 다크 모드 색상 세트입니다. 지정하지 않으면 `colors`를 사용합니다.    |
| `description`  | `string`                 | 아니오    | 사람이 읽을 수 있는 선택적 설명입니다.                               |
| `icon`         | `string`                 | 아니오    | 캘린더 이름 옆에 표시할 이모지 또는 아이콘 이름입니다.               |
| `isVisible`    | `boolean`                | 아니오    | 이 캘린더의 이벤트를 표시할지 여부입니다. 기본값은 `true`입니다.     |
| `isDefault`    | `boolean`                | 아니오    | 이 캘린더를 시스템 기본 캘린더로 표시합니다.                         |
| `readOnly`     | `boolean`                | 아니오    | 이 캘린더의 이벤트에 대해 드래그·크기 조절·편집 UI를 비활성화합니다. |
| `source`       | `string`                 | 아니오    | 출처 레이블입니다(예: `'Google Calendar'`, `'iCloud'`).              |
| `subscription` | `{ url, status, meta? }` | 아니오    | ICS 또는 원격 캘린더의 구독 메타데이터입니다.                        |

**`CalendarColors`의 속성:**

| 속성                 | 타입     | 설명                                   |
| -------------------- | -------- | -------------------------------------- |
| `eventColor`         | `string` | 이벤트 배경색입니다(보통 반투명).      |
| `eventSelectedColor` | `string` | 이벤트가 선택되었을 때의 배경색입니다. |
| `lineColor`          | `string` | 강조 또는 테두리 색상입니다.           |
| `textColor`          | `string` | 이벤트 텍스트 색상입니다.              |

### theme

`theme` 설정은 캘린더 전체의 시각적 외형을 제어합니다:

```tsx
const calendar = useCalendarApp({
  theme: {
    mode: 'dark', // 'light' | 'dark' | 'auto'
  },
});
```

**테마 모드:**

- `'light'`: 밝은 배경과 어두운 글자를 사용하는 라이트 모드(기본값)
- `'dark'`: 어두운 배경과 밝은 글자를 사용하는 다크 모드
- `'auto'`: 시스템 테마 설정을 자동으로 따릅니다

**코드로 테마 바꾸기:**

```tsx
// Get current theme
const currentTheme = calendar.app.getTheme();

// Set theme
calendar.app.setTheme('dark');

// Subscribe to theme changes
calendar.app.subscribeThemeChange(theme => {
  console.log('Theme changed to:', theme);
});
```

**다크 모드 색상 직접 지정하기:**

캘린더 타입마다 라이트 모드와 다크 모드에 서로 다른 색상을 지정할 수 있습니다:

```tsx
const calendars = [
  {
    id: 'work',
    name: 'Work',
    colors: {
      // Light mode colors
      lineColor: '#0066cc',
      eventColor: '#e6f2ff',
      eventSelectedColor: '#cce4ff',
      textColor: '#003d7a',
    },
    darkColors: {
      // Dark mode colors
      lineColor: '#4da6ff',
      eventColor: '#1a3d5c',
      eventSelectedColor: '#2a5a8a',
      textColor: '#b3d9ff',
    },
  },
];
```

테마에 대한 전체 문서는 [다크 모드](/docs-ko/features/dark-mode)를 참고하세요.

### locale

`locale` 옵션은 캘린더의 언어와 지역 설정을 지정합니다.

- **문자열:** `'en-US'`, `'ja'`, `'zh'`, `'de'`, `'fr'`, `'es'`, `'ko'` 같은 언어 코드를 사용합니다.
- **Locale 객체:** 타입 안전성을 위해 가져온 `Locale` 객체를 전달하거나, 지원되지 않는 언어라면 직접 만든 객체를 전달합니다.

```tsx
// String code
const calendar = useCalendarApp({
  locale: 'ja',
});

// Additional Locale object from the localization plugin
import { ja } from '@dayflow/plugin-localization';
const calendar = useCalendarApp({
  locale: ja,
});

// Custom Locale object
const customLocale = {
  code: 'it',
  messages: { today: 'Oggi', ... }
};
const calendar = useCalendarApp({
  locale: customLocale,
});
```

### calendarSystem

`calendarSystem`은 날짜를 표시하고 이동할 때 사용할 달력을 선택합니다. `'gregorian'`(기본값, 양력) 또는 `'jalali'`(페르시아 태양력)입니다. `locale`, `timeZone`, `startOfWeek`와 독립적이므로 영어 UI로 잘랄리력 날짜를 표시하거나 페르시아어 UI로 양력 날짜를 표시할 수 있습니다.

```tsx
import { createLocalizationPlugin, fa } from '@dayflow/plugin-localization';

const calendar = useCalendarApp({
  calendarSystem: 'jalali',
  locale: 'fa-IR',
  timeZone: 'Asia/Tehran',
  plugins: [createLocalizationPlugin({ locales: [fa] })],
  views: [
    createMonthView({ startOfWeek: 6 }), // 주의 시작을 토요일로
    createWeekView({ startOfWeek: 6 }),
    createYearView({ mode: 'grid', startOfWeek: 6 }),
  ],
});
```

바뀌는 것은 표시와 이동뿐입니다. 이벤트 데이터, 콜백, ICS 가져오기, 반복 규칙은 ISO 날짜를 그대로 사용하며, 달력을 바꿔도 이벤트는 수정되지 않습니다.

### useEventDetailDialog

- `true`로 설정하면 기본 모달 대화상자(`DefaultEventDetailDialog`)가 켜집니다.
- `DayFlowCalendar`의 `eventDetailContent`나 `eventDetailDialog`와 함께 사용하면 코어의 상태 관리는 그대로 두고 UI만 교체할 수 있습니다.

### eventDetailTrigger

- `'dbClick'`(기본값): 한 번 클릭하면 이벤트가 선택되고, 더블 클릭하면 상세 패널·대화상자가 열립니다.
- `'click'`: 한 번 클릭하면 상세 패널·대화상자가 바로 열립니다.
- 터치 입력은 이 옵션과 무관하게 동일합니다. 이벤트를 탭하면 상세가 열립니다.

```tsx
const calendar = useCalendarApp({
  views: [createMonthView()],
  eventDetailTrigger: 'click',
});
```

### useCalendarHeader

- `true`(기본값): 내장 캘린더 헤더를 렌더링합니다.
- `false`: 헤더를 완전히 숨깁니다.

직접 만든 헤더를 렌더링하려면 `DayFlowCalendar`의 `calendarHeader` 슬롯을 사용하세요. 자세한 내용은 [캘린더 헤더](/docs-ko/features/calendar-header)를 참고하세요.

### readOnly

- `true`: 내장 편집 UI(드래그, 생성, 편집)를 비활성화합니다.
- `ReadOnlyConfig`: 세부적으로 제어합니다.
  - `draggable`: 드래그 허용 여부입니다.
  - `viewable`: 이벤트 상세를 열 수 있는지 여부입니다.
- `calendar.addEvent()`, `calendar.updateEvent()`, `calendar.deleteEvent()`, `calendar.applyEventsChanges()` 같은 코드 기반 API는 읽기 전용 모드에서도 그대로 동작합니다.
- 직접 만든 UI에서는 `calendar.canMutateFromUI()`로 생성·편집·삭제 컨트롤을 표시할지 판단하세요.
- 자세한 내용은 [읽기 전용 모드](/docs-ko/features/read-only)를 참고하세요.

### allDaySortComparator

모든 뷰(일, 주, 월, 아젠다, 연)에서 종일 이벤트 행의 정렬 순서를 제어합니다.

기본적으로 DayFlow는 다음과 같이 동작합니다:

- 종일 이벤트를 처음 등장한 순서대로 `calendarId` 기준으로 묶습니다
- 여러 날에 걸친 종일 이벤트를 하루짜리 종일 이벤트보다 위에 둡니다
- 같은 캘린더의 종일 이벤트를 시각적으로 모아 둡니다

최종 순서를 완전히 직접 정하고 싶을 때만 `allDaySortComparator`를 전달하세요. 지정하면 비교 함수의 결과가 그대로 사용됩니다.

비교 함수를 전달하면 정렬을 완전히 제어할 수 있습니다. 두 개의 `Event` 객체를 받으며 JavaScript의 `Array.sort`와 동일하게 동작합니다:

```tsx
const calendar = useCalendarApp({
  allDaySortComparator: (a, b) => a.title.localeCompare(b.title),
});
```

`@dayflow/core`에서 **내보내는 헬퍼 함수**:

| 헬퍼                | 동작                                                                                |
| :------------------ | :---------------------------------------------------------------------------------- |
| `sortAllDayByTitle` | 종일 이벤트를 제목 기준 알파벳순으로 정렬하며, 기본 그룹화 방식을 완전히 대체합니다 |

```tsx
import { sortAllDayByTitle } from '@dayflow/core';

const calendar = useCalendarApp({
  allDaySortComparator: sortAllDayByTitle,
});
```

런타임에 정렬을 바꾸려면 `updateConfig`를 사용하세요:

```tsx
calendar.app.updateConfig({ allDaySortComparator: sortAllDayByTitle });

// Restore the default calendar-grouped ordering
calendar.app.updateConfig({ allDaySortComparator: undefined });
```

## 고급 설정 예시

```tsx
import {
  useCalendarApp,
  DayFlowCalendar,
  createMonthView,
  createWeekView,
  ViewType,
} from '@dayflow/react'; // or '@dayflow/vue', '@dayflow/svelte', '@dayflow/angular'
import { createSidebarPlugin } from '@dayflow/plugin-sidebar';
import '@dayflow/core/dist/styles.css';

const calendars = [
  {
    id: 'work',
    name: 'Work',
    colors: {
      eventColor: '#2563eb',
      eventSelectedColor: '#1d4ed8',
      lineColor: '#1e40af',
      textColor: '#ffffff',
    },
  },
  {
    id: 'personal',
    name: 'Personal',
    colors: {
      eventColor: '#f97316',
      eventSelectedColor: '#ea580c',
      lineColor: '#c2410c',
      textColor: '#ffffff',
    },
  },
];

export function AdvancedCalendar() {
  const calendar = useCalendarApp({
    views: [createMonthView(), createWeekView()],
    defaultView: ViewType.WEEK,
    initialDate: new Date('2024-10-01'),
    events: [],
    calendars,
    defaultCalendar: 'work',
    switcherMode: 'select',
    callbacks: {
      onEventUpdate: event => api.events.update(event),
      onVisibleRangeChange: (start, end, reason) =>
        preloadVisibleRange(start, end, reason),
    },
    plugins: [
      createSidebarPlugin({
        width: 280,
        initialCollapsed: false,
      }),
    ],
    useEventDetailDialog: true,
  });

  return <DayFlowCalendar calendar={calendar} />;
}
```

> 팁: `useCalendarApp`이 반환하는 객체는 상태(`currentView`, `currentDate`, `events`)와 동작을 모두 제공합니다. 같은 인스턴스를 `DayFlowCalendar`, 직접 만든 툴바, 사이드 패널과 공유하면 모든 것이 동기화된 상태로 유지됩니다.
